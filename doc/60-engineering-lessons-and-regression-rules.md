# 工程失敗類型與防止重犯

此為公開、通用化的控制清單；不包含原始現場紀錄、裝置身分或內部證據位置。既有 GD 編號保留作程式／測試脈絡，不代表本公開快照已通過所有歷史實機驗收。

## 每次修改

1. 核對參照基線、目前來源與相鄰已驗證修正，保留尚未交付的累積修正；不得從舊副本重做而漏修。
2. 記錄最小失敗情境，在真正出錯的邊界測試，例如下載包、既有設定、舊更新器、資料規模或真實 ACL。
3. 區分缺檔、混版、權限、腳本政策、占用、連線及容量；沒有證據不能混稱根因。
4. 只跑相稱且明確允許的測試，不自動啟動本機中心、實際端點或無差別 OS 操作。
5. 分開報告來源修正、整合、打包、交付、部署與現場驗收。保留失敗，不假改收據或倒填成功。

## 遠端與完整打包

- 移動／放大／焦點切換、尚未就緒時釋放鍵鼠、撤權、網路恢復及視窗關閉都需測生命週期；視訊已連線不等於有影格或可操作。
- 保留輸入順序、同意、租約、桌面世代、畫面 ACK、隊列上限及過期輸入拒絕；不能靠延長時效或放寬 owner 取得測試通過。
- 原生 artifact 必須與目前來源、收據及 cohort 對應。成品必須驗證實際 PYZ、深層依賴及包內角色，不只執行 help。
- 完整管理中心統一 `Build-Management.cmd`；不得手工拼 DLL、改歷史 recipe 字串或失敗後挑舊成功收據。
- 使用新版本／修訂，不覆寫封存；實際 ZIP、中文／空白路徑、NTFS 繼承與 CMD 碼頁需測試。
- 測試 fixture 要隔離呼叫端的 build-selection 環境變數。深層 checkout 的路徑長度錯誤不能誤稱端點安裝或 Defender 問題。
- 缺少私有歷史 artifact 就明確停止；去識別化公開來源不能冒稱原封存 bytes，也不產生假的歷史驗收證據。


## 2026-11-12：累積改善與108啟動格式修正

108沿用105功能基線並累積輸入與媒體改善：排隊過期的presented確認丟棄，不釋放仍合法的拖曳；過期input仍清理。增加固定計數、非模態診斷與拒絕提示；MFT動態碼率、變化合併及真正影格時間戳不藉放寬安全時效取得通過。上游使用者回報108目前功能測試良好並要求新訂版；公開參照版本同步為108／001，不表示本公開來源已產生同bytes的安裝成品。

107的狀態格式升為96 bytes／schema2時，私有媒體入口第一筆stats仍送16 bytes／schema1。真正encode_media會在SDP／grant／第一張影格迴圈前拒絕，媒體程序退出。108讓初始及週期stats共用media_stats_payload，版本、長度與保留字集中產生；media_wire_probe走同一producer→encode→decode，驗零啟動狀態、22個非零計數offset、方向及保留字。舊16-byte格式仍拒絕，不以放寬parser、lease或owner修啟動。

更新狀態格式時，必須盤點所有producer：初始、週期、失敗／清理及所有consumer。合成peer可傳影格、動態碼率測試通過，不等於產品第一筆IPC已能送出。來源、成品、角色與整套cohort要逐項核對；不要只改單一DLL或把建置成功當現場驗收。

本公開更新另外執行離線來源及開發工具回歸，實際結果在provenance/publication.json。原生公開來源未在這次publication重新建置；私有上游的15核心、18媒體、195來源零skip及21真ZIP檢查不冒充公開快照測試。上游曾有同一未變動handoff probe的單次低吞吐，原門檻後續通過仍保留該波動，不能宣稱全面效能改善。未簽章、企業防護及大量端點持續負載仍須另驗；不公開現場記錄。
